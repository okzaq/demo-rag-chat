# PDF参照 RAGチャット（自主制作デモ）

> **本リポジトリは自主制作のポートフォリオです。** 架空の製品マニュアル・FAQを知識源にしたデモであり、
> 実案件の納品物ではありません。

ドキュメントを検索し、**出典付きで回答する** RAG（検索拡張生成）チャットです。
同梱の架空マニュアルに加え、手元のPDFをアップロードして質問することもできます。

**デモURL**: https://demo-rag-chat.vercel.app

## 特徴

- **出典表示**: 回答の根拠に必ず【n】の出典番号を付け、参照したチャンク（ドキュメント名・セクション/ページ）を提示
- **ハルシネーション対策**: 検索でヒットした抜粋だけを根拠に回答させ、根拠がなければ「確認できない」と答えるプロンプト設計
- **PDFアップロード対応**: ページ番号を出典として保持したままチャンク化して検索対象に追加

## 構成: フレームワークに頼らない自前実装

RAGの品質を左右する3要素（チャンク設計・検索設計・プロンプト設計）を、
ライブラリ任せにせずすべて自前で実装しています。

```
質問
 │
 ├─ ① チャンク分割（chunking.py）
 │     Markdownは見出し構造で、PDFはページ単位で分割。
 │     長いセクションのみ文境界を優先した重なり付き分割
 │
 ├─ ② 検索（search.py）
 │     依存ゼロの自前BM25。日本語は文字バイグラムでトークン化
 │     （辞書不要・サーバーレスで軽量。大規模化する場合は
 │       ベクトル/ハイブリッド検索への置き換えを想定した分離設計）
 │
 └─ ③ 回答生成（rag.py / Claude API）
       ヒットした抜粋のみをコンテキストに注入し、出典番号付きで回答
```

### サーバーレス前提のステートレス設計

アップロードされたPDFはサーバーに保存しません。チャンク化した結果をクライアントに返し、
質問のたびにリクエストへ載せて往復させる設計です（Vercelのようにインスタンス間で
状態を共有できない環境でも、どのインスタンスに当たっても正しく動作します）。

## 技術構成

- **バックエンド**: Python 3.12+ / FastAPI / pypdf
- **検索**: 自前BM25（文字バイグラム + 英数字単語のハイブリッドトークン化）
- **AI回答**: Claude API（Anthropic）— コスト最適化のため Haiku モデルを使用
- **フロントエンド**: 素のHTML/JavaScript（依存なし）
- **デプロイ**: Vercel（サーバーレス）
- **コスト保護**: IPごとのレート制限（30回/日）・PDF 2MB/100ページ上限

APIキー未設定の環境では、検索は実動作し、回答生成のみモックになります。

## ローカルで動かす

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
# → http://localhost:8000
```

Claude APIによる実回答を試す場合（未設定ならモック回答）:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

テスト（APIキー不要）:

```bash
python tests/test_rag.py
```
